```
AlphaMind
```

## 2. 核心分析功能

### 2.1 分析模式

系统支持两种独立的分析模式，通过 `StrategyModeResolver` 按优先级解析：

| 优先级 | 参数/来源 | 说明 |
|--------|-----------|------|
| 1（最高） | `mode` 参数 | 显式指定 `PIPELINE` 或 `DEBATE` |
| 2 | `enableDebate` 布尔参数 | `true` → DEBATE，`false` → PIPELINE（兼容旧版本） |
| 3（最低） | 策略默认值 | AGGRESSIVE 默认 PIPELINE；CONSERVATIVE / BALANCED 默认 DEBATE |

#### Pipeline 流水线模式

```
MarketAgent → TechnicalAgent → SentimentAgent → PortfolioAgent → 最终报告
```

- 各 Agent 顺序执行，后一个 Agent 消费前一个 Agent 的上下文
- 适合快速决策场景（激进策略）
- 流程简洁，延迟低

#### Debate 辩论模式

```
MarketAgent → TechnicalAgent → SentimentAgent
       ↓（共享上下文）
BullAgent + BearAgent + NeutralAgent（并行）
       ↓
ArbitratorAgent → 最终裁决报告
```

- 多方视角对同一股票进行攻防辩论，仲裁者综合输出最终结论
- 适合审慎决策场景（保守/平衡策略）
- 结论更全面，但延迟稍高

### 2.2 SSE 流式分析

- **接口**：`GET /api/v1/analysis/stream`
- 使用 **Server-Sent Events（SSE）** 协议推送进度和结果
- 前端使用 `EventSource` 接收，`useSSE.ts` 封装为可复用 Hook
- SSE 事件类型：

| event 名称 | 含义 | payload |
|------------|------|---------|
| `stage` | 分析阶段进度 | `{ stage, message, progress }` |
| `message` | Agent 输出片段 | `{ agentType, data, ... }` |
| `result` | 最终完整报告 | `ApiResponse<AnalysisReportDTO>` |
| `error` | 分析失败 | `ApiResponse<null>` |

- SSE 心跳间隔：30 秒（可配置）
- 自动重连：配置 `sse.reconnect-enabled: true`

### 2.3 同步分析

- **接口**：`POST /api/v1/analysis/analyze`
- 适合服务间调用或不需要流式进度的场景
- 返回完整 `AnalysisReportDTO`

### 2.4 分析历史查询

- **接口**：`GET /api/v1/analysis/history`
- 支持按 `stockCode` 过滤，`limit` 分页（最大 50 条）
- 数据持久化至 PostgreSQL `analysis_reports` 表
- 运行时额外维护一个 `ArrayDeque`（最近 50 条），进程重启后清空

### 2.5 AnalysisReportDTO 结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String(UUID) | 报告唯一标识 |
| `stockCode` | String | 股票代码 |
| `stockName` | String | 股票名称 |
| `finalSignal` | Enum | BUY / SELL / HOLD |
| `confidence` | Object | `value`（0~1）+ `level`（HIGH/MEDIUM/LOW） |
| `tradeSignal` | TradeSignalDTO | 入场价、目标价、止损价、持仓天数、理由 |
| `marketData` | Object | MarketAgent 完整输出 |
| `technicalIndicators` | Object | TechnicalAgent 完整输出 |
| `sentimentData` | Object | SentimentAgent 完整输出 |
| `judgment` | JudgmentDTO | ArbitratorAgent 辩论仲裁结果（DEBATE 模式） |
| `strategy` | String | 使用的策略 |
| `createdAt` | Timestamp | 创建时间 |

## 3. Agent 系统

### 3.1 Agent 一览

| Agent | 类名 | 职责 | 输出上下文键 |
|-------|------|------|-------------|
| MarketAgent | `MarketAgent` | 获取并分析市场行情数据、K 线、基本面指标 | `marketData` |
| TechnicalAgent | `TechnicalAgent` | 计算技术指标（MACD/RSI/KDJ/布林带）、识别形态 | `technicalIndicators` |
| SentimentAgent | `SentimentAgent` | 分析新闻舆情、市场情绪、资金流向 | `sentimentData` |
| PortfolioAgent | `PortfolioAgent` | 综合前三 Agent 输出，给出投资组合建议和交易信号 | `tradeSignal` |
| BullAgent | `BullAgent` | 辩论模式：从多方视角挖掘买入理由 | `bullArguments` |
| BearAgent | `BearAgent` | 辩论模式：从空方视角分析风险因素 | `bearArguments` |
| NeutralAgent | `NeutralAgent` | 辩论模式：提供中性客观分析 | `neutralAnalysis` |
| ArbitratorAgent | `ArbitratorAgent` | 辩论模式：综合多方论据，输出最终裁决 | `judgment` |

> SentimentAgent 的新闻数据来自真实新闻源（`com.alphamind.news` 模块，东方财富个股新闻接口，Redis/本地两级缓存 + 过期降级）；新闻源不可用时基于行情信号分析并显式标注，不编造新闻数量。

### 3.2 BaseAgent 规范

所有 Agent 继承 `BaseAgent`，遵循以下规范：

- **共享状态**：通过 `ThreadLocal<Map<String, Object>>` 传递，公共键名见下表
- **必须调用 `clearContext()`**：每次请求完成后（含异常路径）清理 ThreadLocal，防止线程池泄漏
- **LLM Fallback 链**：`LlmManager`（多模型）→ `ChatClient`（单模型）→ 模板输出；LLM 不可用时不抛异常

**通用上下文键：**

| Key | 含义 |
|-----|------|
| `stockCode` | 股票代码 |
| `stockName` | 股票名称 |
| `strategy` | 策略类型 |
| `marketData` | 市场数据 |
| `technicalIndicators` | 技术指标 |
| `sentimentData` | 舆情数据 |
| `tradeSignal` | 交易信号 |
| `confidence` | 置信度 |
| `sessionId` | 会话ID |
| `contextSummary` | 会话上下文摘要 |

### 3.3 AgentRouter（@mention 消息路由）

- **触发方式**：消息中包含 `@AgentName` 前缀
- **语法**：`@Market 请分析一下` / `@PortfolioAgent 建议买入吗`
- **大小写不敏感**，支持全名（`@MarketAgent`）和简称（`@Market`）
- **8 个可路由 Agent**：Market / Technical / Sentiment / Portfolio / Bull / Bear / Neutral / Arbitrator
- **未命中处理**：无法识别的 @mention 回退到显式 `agentType` 参数，最终默认 PORTFOLIO

## 4. 策略系统

### 4.1 三种策略对比

| 参数 | 保守（CONSERVATIVE） | 平衡（BALANCED） | 激进（AGGRESSIVE） |
|------|---------------------|-----------------|-------------------|
| 仓位比例 | 30% | 50% | 80% |
| 止损比例 | 5% | 7% | 10% |
| 建议持仓天数 | 45 天 | 30 天 | 15 天 |
| 置信度阈值 | 75% | 65% | 55% |
| 买入目标涨幅基准 | 8% | 10% | 12% |
| 默认分析模式 | DEBATE | DEBATE | PIPELINE |
| 前端标识（小写） | `conservative` | `balanced` | `aggressive` |

### 4.2 StrategyModeResolver（模式解析器）

三级优先级逻辑：

```
mode 参数（显式）
  ↓ 无
enableDebate 参数（兼容旧接口）
  ↓ 无
strategy.getDefaultMode()（策略默认）
```

### 4.3 StrategySignalPlanner（交易信号计划生成器）

根据技术评分、舆情评分和策略参数自动生成交易信号：

| 综合评分 | 信号 | 说明 |
|----------|------|------|
| ≥ 70 | BUY | 技术面与舆情共振满足买入条件 |
| 50 ~ 70 | HOLD | 信号中性，继续观察 |
| < 50 | SELL | 综合评分偏弱，控制风险 |

- 若评分 ≥ 70 但置信度低于策略阈值，信号降级为 HOLD
- 自动计算入场价、目标价、止损价

## 5. 对话（Chat）系统

### 5.1 会话管理

| 功能 | 接口 | 说明 |
|------|------|------|
| 创建会话 | `POST /api/v1/chat/session` | 返回 `sessionId`，支持关联 `stockCode` + `strategy` |
| 获取历史 | `GET /api/v1/chat/history/{sessionId}` | 按时间升序，支持 `limit` 参数（默认 20） |
| 清除会话 | `DELETE /api/v1/chat/session/{sessionId}` | 删除 DB 记录 + Redis 缓存 + 内存上下文 |

### 5.2 消息收发

| 模式 | 接口 | 说明 |
|------|------|------|
| 同步消息 | `POST /api/v1/chat/message` | 立即返回 Agent 回复，适合简单集成 |
| SSE 流式消息 | `GET /api/v1/chat/stream/{sessionId}` | Agent 边生成边推送，实时展示思考过程 |

**SSE 流式对话事件：**

| event | 含义 |
|-------|------|
| `thinking` | Agent 正在分析中（状态占位） |
| `message` | Agent 回复内容 |
| `error` | 处理失败 |

### 5.3 @mention 路由

用户消息中可使用 `@AgentName` 精确指定对话的 Agent：

```
用户：@Technical 最近的 MACD 信号如何？
用户：@Bull 给我一个看多的理由
用户：@Arbitrator 综合来看应该买入还是卖出？
```

无 @mention 时，按请求参数 `agentType` 路由，默认 PORTFOLIO。

### 5.4 上下文管理

- 每条消息写入 Redis（`alphamind:session:{sessionId}`，TTL 24 小时）
- 消息同时持久化到 PostgreSQL `chat_messages` 表
- 上下文摘要：每次 Agent 调用前读取最近 N 条消息生成摘要
  - 优先从 Redis 摘要缓存（TTL 30 分钟）读取
  - 缓存未命中时：LLM 可用 → AI 智能摘要；LLM 不可用 → 模板摘要
- `message_count` 通过 `touchSession()` 单条 UPDATE 语句原子递增

## 6. 股票数据功能

### 6.1 股票搜索

- **接口**：`GET /api/v1/stocks/search?query={keyword}`
- 支持按股票代码或名称模糊搜索
- 返回 `StockSearchResult`：代码、名称、市场、行业、最新价、涨跌幅
- 当前版本使用内置模拟数据库（`ConcurrentHashMap`），覆盖主要 A 股品种

### 6.2 股票详情

- **接口**：`GET /api/v1/stocks/{code}`
- 按精确代码查询单只股票详情

### 6.3 每周低位价值股推荐

- **接口**：`GET /api/v1/stocks/recommendations/weekly`
- 每周自动筛选 3 支低估值价值股
- 返回 `WeeklyStockRecommendation`：代码、名称、当前价、推荐理由、目标价
- 首页展示，为用户提供发现优质标的的入口

### 6.4 自选股管理

| 功能 | 接口 | 说明 |
|------|------|------|
| 查询自选股 | `GET /api/v1/stocks/watchlist?userId=default` | 按添加时间倒序 |
| 添加自选股 | `POST /api/v1/stocks/watchlist/{code}` | 同一用户不可重复添加 |
| 移除自选股 | `DELETE /api/v1/stocks/watchlist/{code}` | 按 `userId + stockCode` 精确删除 |
| 检查是否添加 | `GET /api/v1/stocks/watchlist/{code}/check` | 返回 `Boolean` |

- 数据持久化至 PostgreSQL `watchlist_items` 表
- `userId` 默认为 `"default"`，预留多用户扩展接口

## 8. 报告导出

支持从历史记录页将分析报告导出为三种格式：

### 8.1 JSON 导出

- **格式**：原始 `AnalysisReportDTO` JSON
- **文件名**：`{stockCode}_{stockName}_{timestamp}.json`
- 包含完整分析数据，适合程序化处理

### 8.2 Markdown 导出

- **格式**：结构化 Markdown 文档
- **文件名**：`{stockCode}_{stockName}_{timestamp}.md`
- **内容章节**：
  - 基本信息（时间、信号、置信度）
  - 交易建议（入场价、目标价、止损价、持仓天数）
  - 市场数据（价格、涨跌幅、成交量、换手率）
  - 技术面（评分、MACD、RSI、KDJ）
  - 舆情面（评分、趋势、摘要、利好/风险因素）
  - 辩论结果（多方/空方/中性论点，仲裁裁决）

### 8.3 PDF 导出

- **格式**：PDF 文件
- **文件名**：`{stockCode}_{stockName}_{timestamp}.pdf`
- 基于 Markdown 内容生成

## 9. 工程能力管理（Admin）

### 9.1 提示词版本管理

- **路径前缀**：`/api/v1/admin/prompts`
- 支持对每个 AgentType 独立管理提示词版本
- 每个 Agent 最多保留历史版本上限（`MAX_VERSIONS_PER_AGENT`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/prompts` | GET | 获取所有已托管 AgentType 列表 |
| `/prompts/{agentType}` | GET | 获取当前生效的提示词 |
| `/prompts/{agentType}/versions` | GET | 获取历史版本列表（倒序） |
| `/prompts/{agentType}` | POST | 创建新版本并立即激活（Body: `content` + `changeLog` + `createdBy`） |
| `/prompts/{agentType}/rollback/{version}` | POST | 回滚到指定历史版本 |

**版本状态：** `DRAFT` → `ACTIVE` → `DEPRECATED`

### 9.2 LLM 熔断管理

- **路径前缀**：`/api/v1/admin/llm`

| 接口 | 方法 | 说明 |
|------|------|------|
| `/llm/health` | GET | 获取所有模型的熔断状态 |
| `/llm/reset/{model}` | POST | 手动重置指定模型的熔断器（运维用） |

**熔断状态字段（`ModelHealthDTO`）：**

| 字段 | 说明 |
|------|------|
| `provider` | 模型提供商（openai / deepseek / anthropic） |
| `available` | 当前是否可用 |
| `failureCount` | 累计失败次数 |
| `circuitOpen` | 熔断器是否打开 |

## 10. LLM 多模型管理

### 10.1 支持的模型提供商

| 提供商 | 优先级 | 配置键 | 备注 |
|--------|--------|--------|------|
| OpenAI | 主（primary） | `OPENAI_API_KEY` | GPT-4o 等 |
| DeepSeek | 备用 1 | `DEEPSEEK_API_KEY` | 推荐本地开发使用 |
| Anthropic | 备用 2 | `ANTHROPIC_API_KEY` | Claude 系列 |

### 10.2 Fallback 链

```
LlmManager（多模型管理，按优先级轮询）
    ↓ 全部失败
ChatClient（单模型，Spring AI 配置的默认模型）
    ↓ 不可用
模板输出（预定义文本模板，保证系统不崩溃）
```

### 10.3 熔断机制

- 模型连续失败达到阈值 → 自动打开熔断器，暂停调用该模型
- 一段时间后进入半开状态，尝试探测恢复
- 通过 Admin 接口可手动强制重置熔断状态

### 10.4 超时配置

- 单次 LLM 调用超时：120 秒（可配置 `alphamind.llm.timeout-seconds`）

## 11. 记忆系统

### 11.1 三层记忆结构

| 层级 | 实现 | 生命周期 | 适用场景 |
|------|------|----------|----------|
| 短期（会话） | Redis List | 24 小时 TTL | 对话上下文 |
| 中期（历史） | Redis List + PostgreSQL | 每股最多 20 条（Redis）/ 永久（DB） | 分析历史召回 |
| 长期（向量） | Redis Stack Vector Store | 永久 | 相似场景语义检索 |

### 11.2 上下文摘要

- 调用前读取最近消息生成摘要，注入 Agent Prompt
- **LLM 摘要**（优先）：调用 LLM 生成 100 字以内智能摘要
- **模板摘要**（降级）：固定格式拼接对话内容片段
- 摘要缓存于 Redis（`alphamind:summary:{sessionId}`，TTL 30 分钟），避免频繁调用 LLM

### 11.3 降级策略

Redis 不可用时：
- 会话消息 → `ConcurrentHashMap` 内存存储（重启丢失，不影响功能）
- 分析历史 → 返回空列表
- 摘要缓存 → 不缓存，每次实时生成（模板摘要）

### 11.4 配置项

```yaml
alphamind:
  memory:
    enabled: true
    ttl-hours: 24          # 会话 TTL
    vector-dimensions: 1536 # 向量维度（对应 text-embedding-ada-002）
  analysis:
    max-history-recall: 5  # 分析历史最多召回条数
```
