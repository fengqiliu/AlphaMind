# 技术分回测（区分力验证）设计

日期：2026-10-26 · 状态：待确认

## 意图

现有技术分（50 分起，MACD 柱 / RSI12 / KDJ J / 布林位置加减，限幅 10–95，≥70 偏多、<40 偏空）是未经验证的启发式规则。本次只回答一个问题：**在历史上，技术分高的股票，之后的表现是否确实好于分数低的？** 即验证区分力，为以后是否调整阈值、是否值得做校准提供依据。

## 目标 / 非目标 / 反目标

- 目标：用与线上完全相同的评分代码逐日回放历史技术分，按分数分组统计未来收益，给出样本内/样本外结论并写成可复现报告。
- 非目标：舆情分、综合分、规则一致度的回测；修改线上阈值或权重；概率校准；应用内页面或 API。
- 反目标：回测用了一套与线上不同的评分实现（口径漂移）；任何前视偏差（用到信号当日之后的数据）；把回测结果写成“胜率”“可盈利”等投资结论。

## 方案（已选 A）

| 方案                                        | 取舍                                                    |
| ------------------------------------------- | ------------------------------------------------------- |
| **A. 离线回测程序 + Markdown 报告（选定）** | 改动小、可复现，不影响线上；结果只在文档中              |
| B. 后台服务 + 管理接口 + 前端页             | 需异步任务、进度、存储，工作量约 2 倍；结论未出前不划算 |
| C. Python 脚本另写评分                      | 重新实现规则必然漂移，排除                              |

用户选 A：先得到结论，有区分力再考虑产品化。

## 设计要点

### 1. 抽出纯函数评分（唯一口径）

把 `TechnicalAgent.calculateTechnicalIndicators` 的计算部分（校验、EMA/MACD、RSI、KDJ、布林、分项与限幅）抽成无状态的 `TechnicalScoring.score(List<double[]> klines, double price)`，返回现有 `TechnicalIndicatorsDTO`。`TechnicalAgent` 改为调用它，行为与现有测试结果完全不变。回测只调用这个函数。

### 2. 数据

- 股票池：`StockCatalog` 现有 72 只（今日名单，**存在幸存者偏差**，报告中注明）。
- K 线：复用 `EastmoneyKlineMarketDataProvider` 的接口格式，取约 1250 根前复权日 K。技术分的四个指标对价格的线性缩放/平移不变，前复权对信号影响很小；收益用复权价计算，正好包含分红。
- 原始数据缓存到 `backend/backtest-data/`（gitignore），后续重跑可离线完成；报告记录取数日期和每只股票的区间与根数。

### 3. 时间对齐（无前视）

- 每个交易日 t：取截至 t 的**最近 120 根**（与线上 `MARKET_HISTORY_DAYS` 默认值一致，EMA 有记忆，窗口长度必须一致），现价 = t 日收盘，计算技术分。不足 120 根的早期日期跳过。
- 信号在 t 收盘后产生，**t+1 开盘买入**，持有 h 日后在 t+h 收盘卖出；h ∈ {5, 10, 20}。
- t+1 一字涨停（开=高=低=收且较前收涨幅 ≥ 9.5%，创业板/科创板 19.5%）视为无法买入，剔除该样本并计数。停牌缺失日自然不在序列中。
- 单边成本：佣金 0.025% + 滑点 0.05%；卖出另加印花税 0.05%。往返约 0.2%，报告同时给出毛收益与净收益。

### 4. 统计

- 分组：≥70 / [40,70) / <40 三档（线上阈值），另给 10 分一档的细分表看单调性。
- 每档每个 h：样本数、平均与中位数净收益、胜率（净收益>0）、**超额收益**（减去同日全池等权平均的 h 日收益，剔除大盘涨跌）。
- 排序能力：每日横截面 Spearman IC（分数 vs 未来 h 日收益），报告 IC 均值、IC>0 比例；为避免重叠窗口夸大显著性，t 值用全部 IC 的均值、标准误按有效独立样本数（交易日数 / h）放大计算。（2026-10-26 修订：原定“每隔 h 日取一次”的结果随抽样起点在 -0.06 至 1.98 间变化，且与展示的均值不同源；修订不改变本次判定。）
- 样本内/外：按日期前 70% / 后 30% 切分，两段分别报告，结论以样本外为准。
- 区分力判定（事先写死，避免事后挑选）：样本外 h=10 时，“≥70 档平均超额收益 − <40 档平均超额收益 > 0” 且 “IC 均值 > 0 且重叠修正 t 值 > 2”，二者同时满足才写“有区分力”；只满足一项写“弱/不确定”；都不满足写“未见区分力”。

### 5. 运行与产物

- 代码放 `backend/src/main/java/com/alphamind/backtest/`：数据加载（可注入，测试用内存数据）、回放引擎、统计、报告渲染；入口为普通 `main`，不启动 Spring。
- 运行：`mvn -q compile exec:java -Dexec.mainClass=com.alphamind.backtest.TechnicalBacktestMain`（参数：是否刷新数据、输出路径）。`mvn test` 仍完全离线，不触发回测。
- 报告：`docs/回测/技术分回测-YYYY-MM-DD.md`，包含方法、参数、数据区间、所有表格、判定结果和局限说明，明确“历史统计，不构成投资建议”。

### 6. 测试

离线单元测试：纯函数评分与原 `TechnicalAgent` 结果一致（固定序列）；回放不使用 t 之后数据（构造未来暴涨序列，t 日分数不变）；入场为 t+1 开盘、涨停剔除、成本计算；分组与超额收益、Spearman、重叠修正 t 值的手算用例。

## 留给实现者的决定

- 报告表格具体排版、细分档位边界的展示方式。
- 数据缓存文件格式（JSON 即可）。
- 请求间隔（建议 ≥300ms，避免被限流）。

## 局限（报告中照写）

幸存者偏差；72 只样本、约 5 年单一市场阶段；成本为假设值；技术分只是线上综合分的一半，本结论不能推广到综合信号或规则一致度。
