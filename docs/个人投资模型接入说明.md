# 个人投资模型 v1.1 接入说明

依据用户提供的《我的投资模型 v1.1 2026-10-03》，实现价格触发、估值确认、基本面验证、RSI/ATR 择时和组合风险预算。源 Word 文件只读；代码保存规则版本、原文 SHA256 和每次复核的证据快照，不把文档中的旧持仓当作当前账户。

## 使用入口

- `/investment-model`：选择原文 13 个观察标的，填写人工证据与交易后风险值，按最新行情复核并保存。
- 首页分析设置可跳转至个人模型；模型外代码会要求重新选择，不会静默换股。
- `/history?report={id}`：恢复已保存的个人模型报告，支持 JSON、Markdown 和 PDF。
- “载入上次复核”从该标的最新的有来源报告派生草稿；通用分析与空复核不会遮住有来源证据。
- 页面顶部“价格提醒”面板列出未读档位提醒，“去复核”切换到该标的；“我的持仓”维护当前组合，风险预算中“按持仓推算”自动填写 Gate 5 四项。
- 普通分析策略仍对应原有风险参数；个人模型通过专用用例生成五道决策门和风险预算结论。

## 原文规则与工程解释

| 内容 | 实现 |
| --- | --- |
| 13 个标的与三档价格 | 逐项录入 `backend/src/main/resources/investment/personal-model-v1.1.json`；博通集成保留暂定标记 |
| Gate 0 | 精确落入某档才可按该档升级；档间或跌破第三档只触发复核；高于首档为 S0。判定统一由 `PriceZones.classify` 给出（档位重叠取更深一档），价格提醒共用同一口径 |
| Gate 1 | 需要注明来源、报告期、有效期的合理/低估确认；行情缺失的 PE/PB 不替代历史估值证据 |
| Gate 2 | 盈利、扣非、经营现金流及专项条件均需确认；任一否决条件阻止升级 |
| Gate 3 | 核心业务逻辑、价值陷阱检查和反方证据；逻辑受损时提示暂缓及退出复核，不假设已有持仓 |
| Gate 4 | Wilder RSI14、ATR20；周 RSI14 使用已结束周；当期日线/周线及形态由人工确认 |
| 风险预算 | 按交易后单标的、合并主题、现金/低波动和组合回撤评估；未提供不视为满足 |
| 仓位参数 | 普通标的起步控制线 5%，成长科技起步 3%；主题取 20%–25% 的保守端 20%，现金底线 15%，组合回撤 20% |
| 黄金 | 要求合并黄金股、实物黄金、联接基金等暴露，并明确填写黄金矿股 ETF 仓位上限 |
| 分批 | 下一档复核上界取固定下一档上沿与现价减 1.5×ATR20 的更谨慎值；不是下单价 |
| 目标仓位内部比例 | 原文试仓 10%–20%、主建仓/强化各 25%–35%、机动 20%–30% 作为说明，不当作总资产比例 |

原文没有严格定义档间、跌破第三档、形态识别算法与极端超卖后的自动执行规则，本实现采取保守解释：不自动补档、不自动识别底背离、不凭技术指标证明价值。日 RSI14 位于 25–45、当日真实波幅不超过 2×ATR20、当期周线复核通过，才允许技术门通过。RSI14 <25 或行情为过期缓存时不升级为买入候选。

S0 为未进入首档；S1 为仅触发复核或证据不完整；S2 为核心价值证据通过但档位/择时/风险尚不足以升级；第二/第三档满足全部条件后为 S3；进一步低估并确认底背离或波动收敛后才为 S4。只有 S3/S4 标记为建仓/加仓候选，所有级别均不执行交易。

博通集成额外要求估值明显回落、扣非延续改善、OCF 转正或显著改善、库存可被订单消化、Wi-Fi 6/AIoT 收入贡献可验证。利欧、周期股、银行和黄金亦有对应的专项复核条件。

## 数据和保存

- 行情复用现有 Sina/Eastmoney Provider 及缓存降级状态；默认日 K 长度由 60 调整为 120，以支持周线观察。
- 新增统一 `MarketDataMapper`，供行情 Agent 与个人模型复用；上海 ETF 5 开头代码按上海市场请求，并保留三位小数价格。
- 财报与估值历史由 `com.alphamind.fundamental` 自动取数（东方财富数据中心：最新 PE_TTM/PB_MRQ/市值与近 5 年日度估值、最新报告期主要财务指标）。读取顺序为新鲜缓存（6 小时）→ 数据源 → 显式标注的过期缓存（≤30 天）→ 不可用；不编造数值。
- 估值分位只统计正值样本，有效样本少于 240 个交易日或当前值 ≤0（如亏损 PE）时分位为空并说明不适用；银行不使用毛利率/现金流比值提示。
- 自动取数**只作复核参考**：页面展示指标、中性提示和来源，可一键把取数摘要追加到“证据来源与报告期”；Gate 1/2 的结论仍须人工选择，引擎不因分位高低改变门状态。报告冻结保存当次快照（`personalModel.fundamentals`），旧报告该字段为空。ETF 无财报时如实标注不可用。
- 底背离尚无自动可信来源，由用户手工确认。组合数据可由“我的持仓”推算（见下节），持仓本身仍是用户手工维护的声明，未与券商核对。
- 输入包含复核日期、证据有效期、来源/报告期和反方理由。过期或缺失来源不会通过价值确认。
- 个人模型报告的目标价、固定止损价、持有天数和置信度留空；不套用原有短线策略参数。
- V3 增量迁移只增加 `analysis_reports.personal_model` JSONB 列及对象约束，原有报告仍可读取。
- 规则、资产档位、实际行情指标、人工证据、门状态和最终动作共同冻结；历史展示与导出不重新计算。

## 价格提醒

- `PriceAlertJob` 交易时段每 15 分钟（上海时间，`ALPHAMIND_ALERTS_CRON`，设为 `-` 关闭）逐个检查 13 个标的；`POST /alerts/check` 可手动触发，与定时任务共用一把锁。
- 深度：第 1/2/3 档为 1/2/3，跌破第三档为 4，首档之上、档间与未知为 0。`price_alert_state.deepest_alerted` 记录自上次回到首档之上以来已提醒过的最深深度；只有当前深度更深时才写一条提醒，因此档边来回波动只提醒一次。价格回到首档之上时重置为 0。
- 只用实时行情或新鲜缓存；过期缓存与取数失败不提醒、也不更新状态，避免把旧价格当作当前价格。单个标的写入失败不影响其他标的。
- 提醒记录档位变化、价格、行情时间、模型版本，除“已读时间”外不再修改（V8 `price_alerts`、`price_alert_state`）。
- 提醒只表示“该去复核了”，不改变任何决策门，也不产生买入信号。

## 我的持仓与 Gate 5 推算

- 用户在“我的持仓”手动维护持仓（代码、名称、主题、股数或手工市值）、现金、低波动资产（货基/短债等）和组合历史高点；单行保存于 V9 `portfolio_profile`。不对接券商、不同步成交、不记交易流水。
- 有 6 位代码和股数的持仓按实时价估值，否则必须填手工市值（如场外基金）；同一代码不能重复录入；模型内标的的名称与主题以模型为准。
- 推算（`RiskBudgetCalculator`）：拟买入金额从现金与低波动资产中扣除，总资产不变，四项共用同一分母——
  - 交易后单标的权重 =（该标的现有市值 + 拟买入）÷ 总资产
  - 交易后主题合计 =（同主题全部持仓市值 + 拟买入）÷ 总资产
  - 交易后现金及低波动比例 =（现金 + 低波动 − 拟买入）÷ 总资产
  - 组合回撤 =（历史高点 − 总资产）÷ 历史高点；总资产创新高时高点随之上调
- 任一按市价估值的持仓只有过期缓存或取数失败时，四项均不给出并列出原因，不以部分持仓或旧价格凑数；拟买入超过现金与低波动合计、总资产为 0 时同样不给出。未填历史高点时只有回撤需手填。
- 推算值填入表单后仍可手改。证据中冻结 `portfolioBasis`（推算时间、总资产、拟买入金额、各持仓估值来源）；引擎在说明中注明快照来源，表单数值与快照不一致时写明“已被手动修改，以表单为准”。快照不参与门判定，门判定始终使用表单数值。
- “载入上次复核”不沿用组合数值与快照。

## 持仓体检

原文没有明确的卖出或减仓规则（引擎只在 RSI14 过热时提示“复核估值与减速条件”、核心逻辑受损时提示“复核退出条件”），因此体检只使用模型已有参数，不另设止盈线、卖出价或减仓比例：

| 检查 | 范围 | 阈值 |
| --- | --- | --- |
| 单标的超线 | 按市价估值的个股持仓（不含黄金矿股 ETF，其上限为每次复核的人工输入） | 成长科技 3%，其余 5%（模型外个股按 5%） |
| 主题超线 | 13 个标的所属的 7 个主题；用户自填主题不检查 | 20% |
| 现金不足 / 回撤越线 | 整个组合 | 现金及低波动 < 15%；回撤 > 20%（未填历史高点不检查） |
| 过热 | 模型内持仓 | 日 RSI14 > 70 |
| 未复核 / 证据过期 | 模型内持仓 | 没有有来源的复核，或最近一次的证据有效期已过；读取失败按未复核提示 |
| 证据即将过期 | 模型内持仓 | 有效期剩余 0–7 天（到期当天仍有效，与复核引擎同一边界）；已过期的只报“证据过期” |

权重的分母是当前总资产（不含拟买入）。任一按市价估值的持仓只有过期缓存或取数失败时，组合级检查不执行并列出原因，该持仓之外的过热与证据检查照常。体检在打开页面时实时计算，不保存状态。

## 证据复用与重新确认

复用只复制证据来源、反方文字、财报复核日期/有效期、盈利与现金流结论，以及适用的财报专项项。估值、业务逻辑、价值陷阱、日周线择时、底背离/波动收敛、杠杆和所有当前组合数值重新置为未确认或空值；银行/周期/黄金等当前风险项及博通估值回落项亦不继承。

日期不自动延长。过期或日期不完整的来源仍可作为填写草稿，但页面明确提示，模型不会把它作为有效证据升级。没有历史、模型版本不一致或读取失败时，现有表单保留。

新报告在证据中保存 `sourceReportId`，后端验证该来源存在、属于同一标的及当前模型版本；历史详情和导出可回溯来源。载入操作不修改源报告，也不会保存新报告。

V4 增量迁移为有来源的个人报告增加部分索引。查询按股票、时间和 ID 降序在数据库中取一条，不受最近历史列表数量限制；空白、换行、制表符及全角空格不算来源。

## 接口

- `GET /api/v1/investment-model`：定义、版本、原文校验和 13 标的。
- `POST /api/v1/investment-model/analyze`：`{ stockCode, review? }`，获取真实行情、确定性复核并保存报告。
- `GET /api/v1/investment-model/reviews/{stockCode}/latest`：最新有来源复核的安全草稿；无历史返回业务 404、版本不一致返回业务 409。
- `GET /api/v1/investment-model/fundamentals/{stockCode}`：自动取得的财报/估值快照、中性提示与可填入的证据摘要；模型外标的 400，数据源与缓存都不可用（含 ETF 无财报）503。
- `GET /api/v1/investment-model/alerts?includeAcknowledged=false`：最近 50 条提醒（默认只含未读）；`GET /alerts/unread-count`：未读数。
- `POST /api/v1/investment-model/alerts/{id}/ack`：标为已读，重复标记保留首次时间；`POST /alerts/check`：立即检查，上一轮未结束返回业务 409。
- `GET /api/v1/portfolio`：当前组合，未录入返回业务 404；`PUT /api/v1/portfolio`：整体覆盖保存，无法估值或代码重复返回业务 400。
- `GET /api/v1/portfolio/snapshots?days=`：组合每日净值快照与回撤（工作日 15:30 由 `PortfolioSnapshotJob` 记录；缺当期行情的日子无记录）。回撤高点取手填值与快照最大值中较大者，体检与 Gate 5 推算共用。
- `GET /api/v1/portfolio/health`：持仓体检结果（触发项、无法检查的持仓、总资产）；未录入组合返回业务 404。
- `POST /api/v1/portfolio/risk-budget`：`{ stockCode, plannedBuyAmount }`，返回推算结果、各持仓估值来源与问题列表；未录入组合返回业务 404。
- `GET /api/v1/analysis/{reportId}`：复用完整报告读取接口。

## 计算依据

RSI 使用平均上涨/下跌的 Wilder RMA，ATR 使用真实波幅的 Wilder RMA，周期分别取原文的 14 和 20。周线不足时返回空值。

- [TradingView RSI 官方说明](https://www.tradingview.com/support/solutions/43000502338-relative-strength-index-rsi/)
- [TradingView ATR 官方说明](https://www.tradingview.com/support/solutions/43000501823-average-true-range-atr/)
