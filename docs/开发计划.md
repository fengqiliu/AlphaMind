# AlphaMind 开发计划

本文件记录已落地的开发范围和验证边界。代码、当前测试结果优先于旧版说明书中的规划描述。

## 2026-10-16：研究工作台与分析用例整理

目标：让分析入口、运行状态和完整报告更清晰，并使同步/流式分析遵循相同的保存成功规则。

### 实现范围

- 后端 `AnalysisService` 统一分析用例，`AnalysisHistoryService` 集中处理报告保存事务与有界历史查询。
- 报告保存及事务提交失败时，不发送成功结果；流式接口发送具名业务错误，同步接口返回错误响应。
- 前端 `useAnalysisSession` 管理连接、取消、切换股票和完整结果接收；报告通过 store 一次性写入。
- `useSSE` 区分具名业务错误与传输错误，过滤旧连接的排队事件，避免默认消息重复派发。
- 首页拆为设置、流程、行情、舆情等模块，图表在有行情时按需加载。
- 统一浅色界面、青绿色强调色、响应式导航、焦点与减少动画支持；删除静态指数行情和未检测的在线状态。
- 分析设置始终可见，结论仅在完整报告到达后展示；不再为缺失置信度补造 65% 的数值。
- 每周观察支持重试，文案明确其基于样本股价、行业权重和涨跌幅排序。

### 验证范围

- 后端单元/协议回归覆盖：分析与保存顺序、保存异常、成功/失败 SSE、同步错误、有界历史查询。
- 浏览器回归覆盖：搜索、分析完成顺序、取消、切换标的后的过期事件、离开页面后的清理、错误反馈、推荐重试。
- 390 / 768 / 1440 像素宽度检查导航、分析入口和页面溢出；截图位于 `output/playwright/`。
- 普通浏览器测试使用接口拦截数据，不能证明外部行情、真实 LLM 或数据库链路可用。

### 本轮最终验收

- 后端 `mvn test -B -ntp`：56 项通过，0 失败、0 错误、0 跳过（本轮新增 9 项）。
- 前端 `npm run lint`、`npm run build`：通过，TypeScript 检查及所有路由构建完成。
- 浏览器界面与生命周期：71 项通过；真实搜索 → SSE → 完整报告 → 历史接口/页面：1 项通过。
- 真实 DEBATE 接口验收通过：完整报告包含三方观点与仲裁结果，并以 `result → complete` 结束。
- 实际保存失败验证：在本轮独立创建的测试库中临时拒绝报告写入，SSE 只返回具名 `error`，没有 `result` 或 `complete`；移除测试约束后恢复正常。
- PostgreSQL 中 `market_data`、`sentiment_data` 为 JSON 对象，历史接口能正确还原；数据库写入失败未增加报告数量。
- 390 / 768 / 1440 像素空态布局与 390 像素真实报告布局通过；窗口变化后等待图表 ResizeObserver 完成尺寸更新。
- 测试采用 PostgreSQL 16 独立临时容器（15432）、后端 18080、前端 3000。未修改其他项目数据库。
- 行情来自 Sina + Eastmoney，新闻来自 Eastmoney；真实 LLM 调用关闭，解读使用模板降级。Redis 未启动，数据库健康状态为 UP，整体 health 因可选 Redis 为 DOWN。
- 上述结果不覆盖真实 LLM、向量存储、生产部署或鉴权验收。

## 2026-10-20：通用舆情评分的数据缺口与可追溯口径

目标：先消除缺失 PE 被当作亏损、默认市值生成关注度的偏置，让使用者能核对实际评分依据。本轮不扩展个人模型规则。

### 已交付

- PE 缺失/零值/无效值与负 PE 分开处理；可用信号按原始权重归一化，不对缺失项补造观测。
- 排除不足 20 日、含空值/负数或全零的成交量；涨跌幅/换手率缺失时同样剔除相应信号。
- 新闻与行情权重可追溯；所有信号缺失时标记“数据不足”，50 分仅为兼容占位。
- 删除默认市值及由行情拼出的媒体关注度；空头/仲裁器不再从历史估算推断泡沫、催化剂或机构关注。
- 报告增加 `valuationStatus`、`scoreExplanation`、`dataGaps`，使用现有 JSONB 保存，无新数据库迁移。
- 舆情面板增加可折叠的评分依据和缺口说明；JSON、Markdown、PDF 保留同一口径。旧报告不重算，关注度标记为历史估算。
- Prompt 采用与实现一致的趋势阈值，并明确代理评分不是收益概率。
- 算法、边界和示例见 `docs/评分口径与数据缺口.md`。

## 2026-10-21：技术综合评分、规则一致度与辩论证据口径

目标：修正量纲错误、策略对置信度的偏置和辩论无依据断言，明确工程规则与历史收益校准的区别。

### 已交付

- `AnalysisScoringPolicy` 统一等权综合分：技术×0.5+舆情×100×0.5，修正原先总分最高仅75的量纲错误；保持70/50信号门槛与策略执行参数。
- `RULE_AGREEMENT_V1` 使用方向一致性与偏离中性强度，强看多/强看空对称；移除策略仓位加分，受信号覆盖、技术样本元数据及过期缓存上限约束。
- 技术分析需34根有效OHLC；移除虚构近似K线。MACD在有效DIF后预热DEA，平盘RSI为50，MACD零柱不加减分。
- 技术评分保存样本数、说明与分项贡献；RSI中性50不再得到偏多加分，指标显示、模板及仲裁使用一致的70/40技术桶。
- 三方共享 `DebateEvidence`，仅引用已提供证据，区分当前关系与历史交叉、财务缺口与估值结论；移除无依据机构观点、同行排名、独立固定目标和止损。
- 三方基础各1票，技术桶2票、舆情桶1票；保存完整6票，严格过半才裁定看多/看空，不再隐式用角色置信度加票。
- V5新增可空一致度方法字段；页面、历史列表、聊天、Markdown和PDF区分新一致度与旧历史值，旧报告不重算或回填新方法。
- PDF支持被省略的估值键及显式null，修正当日最高价标签；正文按原始文本转义、保留换行，分页避开文字与小型指标卡。
