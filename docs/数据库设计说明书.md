## 1. 概述

AlphaMind 采用 **双存储架构**：

| 层级 | 存储 | 职责 |
|------|------|------|
| 持久层 | PostgreSQL 14+ | 分析报告、自选股、聊天会话与消息、股票基础信息 |
| 缓存层 | Redis 7+ | 会话消息（短期）、分析历史（中期）、上下文摘要缓存 |

PostgreSQL 使用 **Flyway** 进行版本化迁移管理，JPA/Hibernate 6 负责 ORM 映射，`ddl-auto` 设为 `validate`（仅校验，不自动建表）。

Redis 为可选依赖：当 Redis 不可用时，`MemoryService` 自动降级为 `ConcurrentHashMap` 内存存储，系统不中断运行。

## 2. 技术选型

### 2.1 PostgreSQL

- **版本要求**：14+（使用 `JSONB`、`TIMESTAMPTZ`、`GIN` 索引特性）
- **驱动**：`org.postgresql.Driver`（JDBC）
- **连接池**：HikariCP（最大连接数 10，最小空闲 2）
- **时区**：所有时间戳字段使用 `TIMESTAMPTZ`，Hibernate 配置 `jdbc.time_zone=UTC`

### 2.2 Redis

- **版本要求**：7+（可选 Redis Stack 以支持向量存储）
- **客户端**：Lettuce（Spring Data Redis 内置）
- **连接池**：Lettuce Pool（`max-active: 8`，`max-idle: 8`）
- **向量存储**：Spring AI Redis Vector Store，索引名 `alphamind-analysis`，Key 前缀 `alphamind:vec:`

## 3. 数据库配置

### 3.1 连接配置（`application.yml`）

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/alphamind
    username: ${DB_USERNAME:postgres}
    password: ${DB_PASSWORD:postgres}
    driver-class-name: org.postgresql.Driver
    hikari:
      maximum-pool-size: 10
      minimum-idle: 2
      connection-timeout: 30000     # 30秒
      idle-timeout: 600000          # 10分钟

  jpa:
    hibernate:
      ddl-auto: validate            # 仅校验，不自动建表
    show-sql: false
    open-in-view: false
    properties:
      hibernate:
        dialect: org.hibernate.dialect.PostgreSQLDialect
        format_sql: true
        jdbc:
          time_zone: UTC

  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
    validate-on-migrate: true
```

### 3.2 开发环境（`application-dev.yml`）

开发模式下通过 `SPRING_PROFILES_ACTIVE=dev` 启动，该 profile 禁用 PostgreSQL/JPA 自动配置，系统以纯内存模式运行，无需本地数据库。

### 3.3 Docker Compose 服务

```yaml
# docker-compose.yml 中的数据库服务
postgresql:
  image: postgres:14
  ports: ["5432:5432"]
  environment:
    POSTGRES_DB: alphamind
    POSTGRES_USER: postgres
    POSTGRES_PASSWORD: ${DB_PASSWORD}

redis:
  image: redis:7
  ports: ["6379:6379"]
```

## 5. 表结构详细说明

### 5.1 分析报告表 `analysis_reports`

存储每次 AI 分析的完整结果，包括交易信号、置信度和各 Agent 的分析数据（以 JSONB 形式存储）。

```sql
CREATE TABLE IF NOT EXISTS analysis_reports (
    id              VARCHAR(36)  PRIMARY KEY,         -- UUID，由后端生成
    stock_code      VARCHAR(20)  NOT NULL,             -- 股票代码，如 "600519"
    stock_name      VARCHAR(100) NOT NULL,             -- 股票名称，如 "贵州茅台"
    strategy        VARCHAR(20)  NOT NULL DEFAULT 'BALANCED', -- CONSERVATIVE / BALANCED / AGGRESSIVE
    enable_debate   BOOLEAN      NOT NULL DEFAULT TRUE, -- 是否使用辩论模式

    -- 交易信号
    signal_type     VARCHAR(10),                       -- BUY / SELL / HOLD
    entry_price     NUMERIC(12, 4),                    -- 建议入场价
    target_price    NUMERIC(12, 4),                    -- 目标价
    stop_loss       NUMERIC(12, 4),                    -- 止损价
    holding_days    INTEGER,                           -- 建议持仓天数
    rationale       TEXT,                              -- 交易理由

    -- 置信度
    confidence_value   NUMERIC(5, 4),                 -- 0.0000 ~ 1.0000
    confidence_level   VARCHAR(10),                   -- HIGH / MEDIUM / LOW

    -- 完整分析数据（jsonb，结构见第 8 节）
    market_data          JSONB,                        -- 市场/行情数据
    technical_indicators JSONB,                        -- 技术指标数据
    sentiment_data       JSONB,                        -- 舆情数据
    judgment             JSONB,                        -- 辩论仲裁结果

    -- 元数据
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

**字段说明**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | VARCHAR(36) | PK | UUID，由 `PipelineOrchestrator` 在生成报告时赋值 |
| `stock_code` | VARCHAR(20) | NOT NULL | A 股代码（6 位数字），支持沪深两市 |
| `strategy` | VARCHAR(20) | NOT NULL, DEFAULT 'BALANCED' | 分析策略；枚举值 `CONSERVATIVE`/`BALANCED`/`AGGRESSIVE` |
| `enable_debate` | BOOLEAN | NOT NULL | `true` 表示使用 Bull/Bear/Neutral + Arbitrator 辩论模式 |
| `signal_type` | VARCHAR(10) | NULLABLE | 最终交易信号，可能为 `null`（分析失败或仅观望） |
| `confidence_value` | NUMERIC(5,4) | NULLABLE | 归一化置信度，范围 `[0, 1]` |
| `market_data` | JSONB | NULLABLE | MarketAgent 输出，详见 §8.1 |
| `technical_indicators` | JSONB | NULLABLE | TechnicalAgent 输出，详见 §8.2 |
| `sentiment_data` | JSONB | NULLABLE | SentimentAgent 输出，详见 §8.3 |
| `judgment` | JSONB | NULLABLE | ArbitratorAgent 辩论仲裁结果，详见 §8.4 |

### 5.2 自选股表 `watchlist_items`

存储用户收藏的自选股列表，支持多用户（当前默认用户 ID 为 `"default"`）。

```sql
CREATE TABLE IF NOT EXISTS watchlist_items (
    id              BIGSERIAL    PRIMARY KEY,           -- 自增主键
    user_id         VARCHAR(100) NOT NULL DEFAULT 'default', -- 用户标识
    stock_code      VARCHAR(20)  NOT NULL,              -- 股票代码
    stock_name      VARCHAR(100) NOT NULL,              -- 股票名称
    notes           TEXT,                               -- 用户备注
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    UNIQUE (user_id, stock_code)                        -- 同一用户不可重复添加同一股票
);
```

**字段说明**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGSERIAL | PK | 数据库自增，Java 侧映射为 `Long` |
| `user_id` | VARCHAR(100) | NOT NULL, DEFAULT 'default' | 用户唯一标识，预留扩展；当前版本恒为 `"default"` |
| `stock_code` | VARCHAR(20) | NOT NULL | 股票代码 |
| `notes` | TEXT | NULLABLE | 用户自定义备注，可为空 |
| `(user_id, stock_code)` | UNIQUE | — | 复合唯一约束，防止重复添加 |

### 5.3 聊天会话表 `chat_sessions`

记录每个 AI 对话会话的元信息，消息内容存储在 `chat_messages`。

```sql
CREATE TABLE IF NOT EXISTS chat_sessions (
    session_id      VARCHAR(36)  PRIMARY KEY,           -- UUID
    user_id         VARCHAR(100) NOT NULL DEFAULT 'default',
    stock_code      VARCHAR(20),                        -- 关联股票（可为空，支持通用对话）
    stock_name      VARCHAR(100),
    strategy        VARCHAR(20),                        -- 会话使用的分析策略
    message_count   INTEGER      NOT NULL DEFAULT 0,    -- 消息总数（冗余统计字段）
    last_active_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(), -- 最近活跃时间
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

**字段说明**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `session_id` | VARCHAR(36) | PK | UUID，由后端 `ChatController` 创建会话时生成 |
| `stock_code` | VARCHAR(20) | NULLABLE | 可选关联股票；通用对话时为 `null` |
| `message_count` | INTEGER | NOT NULL, DEFAULT 0 | 冗余统计，通过 `ChatSessionRepository.touchSession()` 累加，避免每次 COUNT 查询 |
| `last_active_at` | TIMESTAMPTZ | NOT NULL | 每次收到新消息时更新，用于排序和清理过期会话 |

---

### 5.4 聊天消息表 `chat_messages`

存储会话中每条消息的完整内容，通过外键关联 `chat_sessions`。

```sql
CREATE TABLE IF NOT EXISTS chat_messages (
    id              VARCHAR(36)  PRIMARY KEY,           -- UUID
    session_id      VARCHAR(36)  NOT NULL
                    REFERENCES chat_sessions(session_id)
                    ON DELETE CASCADE,                  -- 级联删除
    role            VARCHAR(20)  NOT NULL,              -- user / assistant / system
    content         TEXT         NOT NULL,              -- 消息正文
    agent_type      VARCHAR(20),                        -- Agent 类型枚举
    agent_name      VARCHAR(50),                        -- Agent 显示名称
    model_used      VARCHAR(50),                        -- 调用的 LLM 模型名
    token_count     INTEGER,                            -- 本条消息消耗的 token 数
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

**字段说明**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | VARCHAR(36) | PK | UUID，由 `ChatMessage` DTO 创建时生成 |
| `session_id` | VARCHAR(36) | FK, NOT NULL | 外键引用 `chat_sessions.session_id`；级联删除 |
| `role` | VARCHAR(20) | NOT NULL | 消息角色：`user`（用户）/ `assistant`（AI）/ `system`（系统提示） |
| `agent_type` | VARCHAR(20) | NULLABLE | Agent 类型：`MARKET` / `TECHNICAL` / `SENTIMENT` / `PORTFOLIO` / `BULL` / `BEAR` / `NEUTRAL` / `ARBITRATOR` |
| `model_used` | VARCHAR(50) | NULLABLE | 记录实际调用的模型，如 `gpt-4o`、`deepseek-chat`，用于成本分析 |
| `token_count` | INTEGER | NULLABLE | Token 消耗量，当 LLM Provider 返回时写入 |

### 5.5 股票基础信息缓存表 `stock_info`

缓存股票的基础信息和最新行情快照，每次分析后由 MarketAgent 更新。

```sql
CREATE TABLE IF NOT EXISTS stock_info (
    stock_code      VARCHAR(20)  PRIMARY KEY,           -- 股票代码（主键）
    stock_name      VARCHAR(100) NOT NULL,              -- 股票名称
    market          VARCHAR(20),                        -- 上海主板 / 深圳主板 / 创业板 / 科创板
    industry        VARCHAR(50),                        -- 所属行业

    -- 最新行情快照（每次分析后 UPSERT）
    current_price   NUMERIC(12, 4),                     -- 最新价格
    change_percent  NUMERIC(8, 4),                      -- 涨跌幅（%）
    market_cap      BIGINT,                             -- 市值（元）
    pe_ratio        NUMERIC(10, 4),                     -- 市盈率

    -- 元数据
    last_updated    TIMESTAMPTZ  NOT NULL DEFAULT NOW(), -- 行情最后更新时间
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

**字段说明**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `stock_code` | VARCHAR(20) | PK | 6 位 A 股代码，如 `600519` |
| `market` | VARCHAR(20) | NULLABLE | 市场分类：`上海主板` / `深圳主板` / `创业板` / `科创板` |
| `market_cap` | BIGINT | NULLABLE | 单位：元，用整型避免浮点精度问题 |
| `last_updated` | TIMESTAMPTZ | NOT NULL | 行情快照时间戳，与 `created_at` 分离，用于判断数据新鲜度 |

## 6. 索引设计

### 6.1 索引汇总

| 表 | 索引名 | 类型 | 字段 | 用途 |
|----|--------|------|------|------|
| `analysis_reports` | `idx_analysis_stock_code` | B-Tree | `stock_code` | 按股票查询历史报告 |
| `analysis_reports` | `idx_analysis_created_at` | B-Tree | `created_at DESC` | 时间倒序分页 |
| `analysis_reports` | `idx_analysis_signal_type` | B-Tree | `signal_type` | 按信号类型筛选 |
| `analysis_reports` | `idx_analysis_market_data` | **GIN** | `market_data` | JSONB 内字段查询 |
| `watchlist_items` | `idx_watchlist_user_id` | B-Tree | `user_id` | 按用户查自选股 |
| `watchlist_items` | `idx_watchlist_stock_code` | B-Tree | `stock_code` | 按股票反查关注用户 |
| `chat_sessions` | `idx_chat_sessions_user` | B-Tree | `(user_id, last_active_at DESC)` | 按用户列出活跃会话 |
| `chat_sessions` | `idx_chat_sessions_stock` | B-Tree | `stock_code` | 按股票查关联会话 |
| `chat_messages` | `idx_chat_messages_session` | B-Tree | `(session_id, created_at ASC)` | 会话消息时序读取 |
| `chat_messages` | `idx_chat_messages_agent` | B-Tree | `agent_type` | 按 Agent 类型筛选消息 |
| `stock_info` | `idx_stock_info_industry` | B-Tree | `industry` | 按行业筛选股票 |
| `stock_info` | `idx_stock_info_market` | B-Tree | `market` | 按市场筛选股票 |

### 6.2 GIN 索引说明

`market_data` 字段使用 GIN（Generalized Inverted Index）索引，支持对 JSONB 内部字段的高效查询：

```sql
-- 创建 GIN 索引
CREATE INDEX idx_analysis_market_data ON analysis_reports USING GIN (market_data);

-- 示例：查询市值超过 1000 亿的分析报告
SELECT * FROM analysis_reports
WHERE market_data @> '{"marketCap": 100000000000}'::jsonb;
```

## 7. 触发器与函数

### 7.1 `updated_at` 自动更新函数

```sql
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

### 7.2 触发器绑定

| 触发器名 | 表 | 时机 | 操作 |
|----------|-----|------|------|
| `trg_analysis_reports_updated` | `analysis_reports` | `BEFORE UPDATE` | 自动更新 `updated_at` |
| `trg_watchlist_items_updated` | `watchlist_items` | `BEFORE UPDATE` | 自动更新 `updated_at` |

> `chat_sessions` 和 `stock_info` 的 `updated_at` 由应用层（Hibernate）负责维护，未绑定触发器。

## 9. Redis 数据结构

### 9.1 Key 规范

| Key 前缀 | 格式 | 数据类型 | TTL | 说明 |
|----------|------|----------|-----|------|
| `alphamind:session:` | `alphamind:session:{sessionId}` | List | 24 小时 | 会话消息列表，存储 `ChatMessage` 序列化对象 |
| `alphamind:history:` | `alphamind:history:{stockCode}` | List | 无（手动管理） | 股票分析历史，每只股最多保留 20 条 |
| `alphamind:summary:` | `alphamind:summary:{sessionId}` | String | 30 分钟 | LLM 生成的上下文摘要缓存 |
| `alphamind:vec:` | `alphamind:vec:{vectorId}` | 向量 | 永久 | Spring AI Redis Vector Store（需 Redis Stack） |

### 9.2 会话消息（`alphamind:session:{sessionId}`）

- 数据类型：Redis List（`rightPush` 追加，尾部为最新消息）
- 元素结构：序列化的 `ChatMessage` 对象（JSON）
- 读取：`opsForList().range(key, -limit, -1)` 取最近 N 条
- TTL：写入时通过 `expire(key, SESSION_TTL)` 刷新为 24 小时

### 9.3 分析历史（`alphamind:history:{stockCode}`）

- 数据类型：Redis List
- 写入：`rightPush` + `trim(-20, -1)`，保证每只股最多 20 条
- 读取：`range(key, -limit, -1)` 取最近 N 条 `AnalysisReportDTO`

### 9.4 摘要缓存（`alphamind:summary:{sessionId}`）

- 数据类型：Redis String
- TTL：30 分钟（防止频繁调用 LLM 生成摘要）
- 降级：Redis 不可用时不缓存，每次请求实时生成（模板摘要）

### 9.5 降级策略

```
Redis 可用 → 正常读写 Redis
Redis 不可用 ─┬─ 会话消息 → ConcurrentHashMap（内存，进程重启后丢失）
              ├─ 分析历史 → 返回空列表（不影响主流程）
              └─ 摘要缓存 → 不缓存，每次调用 generateTemplateSummary() 生成
```

## 10. 数据库迁移策略

### 10.1 Flyway 版本管理

迁移脚本位于 `backend/src/main/resources/db/migration/`，命名规范：

```
V{版本号}__{描述}.sql
```

| 文件 | 版本 | 说明 |
|------|------|------|
| `V1__init_schema.sql` | V1 | 初始化全部表结构、索引、触发器 |

### 10.2 迁移规则

- `baseline-on-migrate: true`：对已有数据库设置基线，避免首次迁移报错
- `validate-on-migrate: true`：启动时校验已执行的迁移脚本未被修改
- **禁止**修改已提交的迁移脚本，需变更时新建下一版本文件（如 `V2__xxx.sql`）
- 生产环境部署前在 staging 环境验证迁移脚本

### 10.3 回滚策略

Flyway Community Edition 不支持自动回滚。回滚方案：

1. 准备对应版本的 `undo` SQL 脚本（手动维护）
2. 通过 `flyway repair` 修复迁移历史后手动执行回滚 SQL
3. 建议每次上线前备份数据库

### 11.2 关键查询示例

```java
// 获取最近 50 条分析报告（内存兜底用）
List<AnalysisReportEntity> findTop50ByOrderByCreatedAtDesc();

// 更新会话活跃时间 + 消息计数（单 SQL，避免乐观锁冲突）
@Modifying
@Query("UPDATE ChatSessionEntity s SET s.lastActiveAt = :time, " +
       "s.messageCount = s.messageCount + 1 WHERE s.sessionId = :id")
void touchSession(@Param("id") String sessionId, @Param("time") OffsetDateTime time);

// 按信号类型查询报告（使用 JPQL）
@Query("SELECT r FROM AnalysisReportEntity r WHERE r.signalType = :signal " +
       "ORDER BY r.createdAt DESC")
List<AnalysisReportEntity> findBySignalType(@Param("signal") String signalType);
```

### 11.3 JPA 实体关联

```
ChatSessionEntity (1) ──── OneToMany ────▶ ChatMessageEntity (N)
  mappedBy = "session"，fetch = LAZY，cascade = ALL，orphanRemoval = true
```

消息实体通过 `@ManyToOne @JoinColumn(name = "session_id")` 引用会话，保证级联删除和懒加载。

## 13. 运维说明

### 13.1 数据保留策略

| 数据类型 | 存储位置 | 保留策略 |
|----------|----------|----------|
| 分析报告 | PostgreSQL | 永久保留（无自动清理） |
| 内存分析历史 | `ArrayDeque`（进程内） | 最近 50 条，重启清空 |
| 自选股 | PostgreSQL | 永久保留 |
| 聊天会话/消息 | PostgreSQL | 永久保留 |
| Redis 会话消息 | Redis | TTL 24 小时自动过期 |
| Redis 分析历史 | Redis | 每只股最多 20 条，手动 TRIM |
| Redis 摘要缓存 | Redis | TTL 30 分钟自动过期 |

### 13.2 健康检查

通过 Spring Boot Actuator 暴露数据库健康状态：

```
GET /actuator/health
```

返回 PostgreSQL（`db`）和 Redis（`redis`）的连接状态，均配置为 `enabled: true`。

### 13.3 备份建议

- **PostgreSQL**：使用 `pg_dump` 每日全量备份，保留 7 天
- **Redis**：开启 AOF 持久化；会话数据重要性低，可接受丢失
- 上线前对迁移脚本在 staging 环境验证，执行 `flyway validate` 确保一致性

### 13.4 性能建议

- `analysis_reports` 表数据量增大后，可按 `created_at` 做月份分区
- `chat_messages` 消息量大时，可增加按 `session_id` 的分区表或归档策略
- 向量检索（Redis Stack）维度为 1536，与 OpenAI `text-embedding-ada-002` 输出维度一致
